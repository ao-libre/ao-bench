# VB6.md — ao-libre branches for aobench

Everything about the two VB6 repositories that power the aobench bot server and
client. Both live on a dedicated `aobench` branch on top of the unmodified
ao-libre master.

---

## Repositories

| Repo | Branch | Purpose |
|------|--------|---------|
| `ao-libre/ao-server` | `aobench` | Game server — adds BotAPI TCP port, anticheat bypass, observer mirroring |
| `ao-libre/ao-cliente` | `aobench` | Game client — adds headless auto-login, observer viewer form |

Both repos are VB6 applications that run on **Windows only**. They compile with
the standard VB6 IDE (`VB6.EXE`) and the `MSWINSCK.OCX` Winsock control.

### BotAPI.bas

The core module. When the server starts, `General.bas` calls
`frmBotAPI.StartListening` which opens `Socket(0)` on port 4200. Each incoming
TCP connection is accepted onto `Socket(1..20)`. Messages are newline-delimited
JSON — one object per line.

**Dispatch flow:**

```
frmBotAPI.frm
  Socket_DataArrival
    → buffer incoming bytes
    → split on Chr(10) (newline)
    → parse each line as JSON via JSON.bas
    → if action = "loginObserver" → BotAttachObserver(slot, charname)
    → if slot is observer → only allow "say" action
    → else → BotDispatch(line)
                → BotDispatchExtended(action, i, parsed)  [for extended actions]
```

**How actions are executed:**

BotAPI does NOT duplicate game logic. Instead, for each action it:
1. Writes the packet ID byte + parameters into `UserList(i).incomingData`
2. Calls the existing protocol handler (e.g. `HandleWalk`, `HandleAttack`)

This means every action goes through the same validation, combat, and XP
award logic as a real player. Example for `walk`:

```vb
' Inject heading byte into incomingData, then call the real handler
InjectByte i, ClientPacketID.Walk
InjectByte i, CByte(h)
Call HandleWalk(i)
```

For actions where the underlying logic is a standalone sub (not a protocol
handler), it calls that directly: `Call MoveUserChar(i, h)` for walk,
`Call UsuarioAtaca(i)` for attack.

**getState serialisation:**

`BotGetState(i)` reads `UserList(i)` at the moment of the call and builds a
JSON string using `cStringBuilder`. It serialises:
- Position (`Pos.X`, `Pos.Y`, `Pos.Map`)
- Heading (from `Char.heading` enum → string)
- HP / mana / stamina (min and max)
- Gold, exp (as `CLng`), level, clase
- All 20 skills (`Stats.UserSkills(1..20)` + `ExpSkills`)
- Inventory slots with item names resolved from `ObjData()`
- Nearby NPCs and players within 8 tiles
- Status effects (`Envenenado`, `Paralizado`, `Meditando`, `Descansar`,
  `Ceguera`, `Estupidez`, `invisible`, `Oculto`)

**Action coverage — 72 total:**

### frmBotAPI.frm

Winsock control array with `Socket(0..20)`.

```
Socket(0)   → listens on port 4200
Socket(1)   → first accepted client
Socket(2)   → second accepted client
...
Socket(20)  → twentieth accepted client (max simultaneous connections)
```

Each socket has its own receive buffer (`m_buffer(0..20) As String`).
`Socket_DataArrival` accumulates chunks, splits on `Chr(10)`, dispatches
complete lines to `BotDispatch`. Partial messages are held in the buffer until
the next `Chr(10)` arrives.

`SendToSlot(slot, data)` sends a response string to a specific socket. Used by
`BotMirrorToObserver` to push packets to the observer connection.

### BOT_SERVER=1 — anticheat bypass

ao-libre enforces minimum intervals between actions (attack, cast, use item) via
`modNuevoTimer.bas`. Without the bypass, a bot acting at machine speed would be
kicked within seconds.

With `BOT_SERVER=1` (a VB6 conditional compilation constant), all 10
`IntervaloPermite*` functions return `True` immediately:

```vb
Public Function IntervaloPermiteAtacar(...) As Boolean
    #If BOT_SERVER Then
        IntervaloPermiteAtacar = True
        Exit Function
    #End If
    ' ... original timer logic ...
End Function
```

The same flag wraps `AddCount` and `CheckInt` in `modAntiCheat.bas` so no
cheat-log messages are written and no admin alerts are sent.

**Important:** `BOT_SERVER=1` only bypasses the *rate limiting kick*. The
game's combat cooldown logic (minimum time between server-side hits) is still
active — bots are fast, not instant.

### Observer mode

A second TCP connection can attach to a running bot and receive all packets the
server sends to that bot in real time.

**Server side (`BotAPI.bas` + `modSendData.bas`):**

1. `ObserverConnID As Long` is added to the `User` type in `Declares.bas`
   (value `-1` = no observer).
2. `BotAttachObserver(slot, charname)` sets `UserList(i).ObserverConnID = slot`
   and immediately replays the current state to the observer.
3. `BotMirrorToObserver(Userindex, data)` is called in `modSendData.bas` after
   every packet written to `UserList(i).outgoingData`. If `ObserverConnID > 0`,
   the packet string is forwarded to `frmBotAPI.SendToSlot(ObserverConnID, data)`.
4. On socket close, the observer loop in `Socket_Close` clears `ObserverConnID`
   for any user that was being observed.
5. Only one observer per bot — a second `loginObserver` for the same charname
   returns `{"ok":false,"error":"Already has an observer"}`.
6. Observer sockets can only send `say` — all other actions return an error.

**Protocol:**
```json
→ {"action":"loginObserver","charname":"Bot1"}
← {"ok":true,"observing":"Bot1"}
← [all subsequent packets sent to Bot1, as JSON-encoded strings]
```

```cmd
  /d UsarQueSocket=1:ConUpTime=1:AntiExternos=0:Lac=1:DEBUGGING=0:BOT_SERVER=1 ^

type vb6build.log
```

The key flag is `/d BOT_SERVER=1`. The other flags match the existing ao-libre
battle server build configuration. Check `vb6build.log` — a successful build
ends with `0 error(s)`.

**Verify the server is working after starting:**
```cmd
netstat -an | findstr 4200
```
Should show `LISTENING` on `0.0.0.0:4200`.

**Smoke test from cmd:**
```cmd
echo {"action":"getState","charname":"test"} | nc localhost 4200
```
Should return `{"ok":false,"error":"Character not found: test"}` — which
confirms the port is open and JSON dispatch works.

### Bot auto-login (`/bot` flag)

Launches the client headlessly, logs in, selects a character, and enters the
game with no user interaction.

**Usage:**
```cmd
Argentum.exe /bot bot@aobench.local mypassword MyBotChar
```

**How it works:**

`General.bas` parses `Command()` (the VB6 built-in for command-line args):
```vb
Case "/BOT"
    If i + 3 <= Upper_t Then
        BotAutoLogin   = True
        BotEmail       = T(i + 1)    ' "bot@aobench.local"
        BotPassword_CL = T(i + 2)    ' "mypassword"
        BotCharName    = T(i + 3)    ' "MyBotChar"
        i = i + 3
    End If
```

`frmConnect.Form_Activate` fires when the connect screen loads:
```vb
If BotAutoLogin Then
    AccountName = BotEmail
    AccountPassword = BotPassword_CL
    txtNombre.Text = AccountName
    txtPasswd.Text = AccountPassword
    Call btnConectarse_Click   ' triggers connection
End If
```

After the server accepts the account login, it sends an `AccountData` packet
with `AccountHash` and the character list. `Protocol.bas` handles this:
```vb
' After parsing cPJ(1..N) character array:
If BotAutoLogin And Len(BotCharName) > 0 Then
    For autoIdx = 1 To NumberOfCharacters
        If UCase$(cPJ(autoIdx).Nombre) = UCase$(BotCharName) Then
            UserName = cPJ(autoIdx).Nombre
            Call WriteLoginExistingChar   ' enters game
            Exit For
        End If
    Next autoIdx
End If
```

The globals in `Declares.bas`:
```vb
Public BotAutoLogin    As Boolean  ' True when /bot flag present
Public BotEmail        As String   ' Account email/name
Public BotPassword_CL  As String   ' Account password (command-line)
Public BotCharName     As String   ' Character name to auto-select
```

### Observer form (`frmObserver.frm`)

A simple form that connects to the BotAPI port (4200) and displays incoming
JSON state in a listbox. Used to watch an AI bot play live.

**Usage:**
- Launch the ao-libre client normally
- A button on `frmConnect` opens `frmObserver`
- Enter the charname to observe, click "Observar"
- The form connects to `127.0.0.1:4200`, sends `loginObserver`, and receives
  all packets the bot receives

```vb
' Sends on connect:
msg = "{""action"":""loginObserver"",""charname"":""" & charname & """}"
ObsSocket.SendData msg & Chr(10)

' Receives state JSON lines and adds to lstState ListBox
lstState.AddItem line
```

The form shows `[OBSERVE MODE] aobench Observer` in its caption and displays
`lblStatus` showing connection state. It does not render the game graphically —
it just shows the raw JSON. For visual observation, use the full client with the
observer login (task 14.7 — pending full implementation).

## Sequence: full bot startup

```
1.  Harness writes Charfile/BOTNAME.chr + Account/BOTNAME.acc + Account/<hash>.ach
    (provisioner.ts — runs on Linux/Mac)

2.  Windows: start server.exe (compiled with BOT_SERVER=1)
    → frmBotAPI.StartListening opens port 4200

3.  Linux/Mac: start gateway
    → BotApiClient connects TCP to 192.168.x.x:4200

4.  Windows: start Argentum.exe /bot email pass BOTNAME
    → frmConnect.Form_Activate fires → auto-clicks connect
    → TCP connect to server port 7666
    → WriteLoginExistingAccount (email + password)
    → server verifies .acc file, returns AccountHash + char list
    → client finds BOTNAME in char list → WriteLoginExistingChar
    → bot character enters the game world

5.  Gateway detects SDK connect:
    → registers polling timer for BOTNAME
    → sends getState to BotAPI every 600ms
    → caches WorldState

6.  Harness / SDK / MCP connects to gateway WebSocket
    → receives first WorldState push
    → starts sending actions

7.  (Optional) Observer connects to port 4200:
    → sends {"action":"loginObserver","charname":"BOTNAME"}
    → receives all server→bot packets in real time
```

## Known issues / gotchas

**`MaxUsers` not `MAX_USERS`**
ao-libre declares the user count as a variable `Public MaxUsers As Integer`,
not a constant. BotAPI.bas loops use `For i = 1 To MaxUsers` — not `MAX_USERS`.

**`BOT_SERVER` is a CondComp constant, not a runtime variable**
It must be passed on the compiler command line (`/d BOT_SERVER=1`). You cannot
toggle it at runtime. The `ai_build_vb6.cmd` script sets it. Builds from the
VB6 IDE without the `/d` flag will compile without the bypass (anticheat active).

**CRLF line endings**
All VB6 source files use CRLF. When editing on Linux, open with `encoding='latin1'`
and write with `newline='\r\n'`. Binary files (`.frx`, `.dll`, `.ocx`) should
never be modified on Linux.

**JSON.bas is already in the server**
`Codigo/JSON.bas` was already present in ao-libre master — it was not added by
aobench. BotAPI.bas calls `parse(jsonMsg)` from it directly.

**cStringBuilder.toString is a Property Get**
The method is `Property Get toString() As String` — read as `sb.toString` (no
parentheses). VB6 is case-insensitive so `sb.ToString` also works.

**Max 20 simultaneous bot connections**
`frmBotAPI.frm` has `Private Const MAX_BOT_CONNECTIONS As Integer = 20`. This
limit is per server process. Increase it in the form if needed.

**Observer slot check scans all users**
`BotIsObserverSlot(slot)` loops `1 To MaxUsers` on every incoming message from
an observer socket. With 550 max users this is fast but it runs on every packet.
Cache the result in frmBotAPI if performance becomes an issue.
